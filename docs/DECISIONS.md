| D12 | 2026-11-09 | Workspace lint table sets `unsafe_code = "forbid"`; `macrunnerbar-macos` (step 3) defines its own `[lints]` table without it instead of inheriting | a new crate is unsafe-free by default; the one crate that may use `unsafe` opts out explicitly, each block with `// SAFETY:` | per-crate `#![forbid(unsafe_code)]` (a forgotten line silently allows unsafe) |
| D13 | 2026-11-09 | `ureq` 3 (`default-features = false`, `rustls` only) is the HTTP client in `macrunnerbar-github` | small blocking client, enough for ~2 polls/min and one download; no gzip, JSON or cookie features pulled in; rustls (ring, bundled roots) avoids a system TLS dependency | `reqwest` + `tokio` (async runtime for nothing), shelling out to `curl` |
| D14 | 2026-11-09 | `serde_json` in `macrunnerbar-github`, parsed to `Value` and read field by field | GitHub payloads are large and mostly unused; no DTO structs to keep in sync; parse errors carry no payload text | typed `Deserialize` structs per endpoint |
| D15 | 2026-11-09 | `sha2` in `macrunnerbar-github` to verify the runner release SHA-256 while streaming the download | required by the plan; RustCrypto, pure Rust | `shasum` subprocess, no verification |
| D16 | 2026-11-09 | `tracing` facade only (no subscriber) in `macrunnerbar-github` for the debug log of JIT `runner.labels` | adapters log through the facade; the app installs the rotating-file subscriber (step 3/5) | `log` crate, no logging in adapters |
| D17 | 2026-11-09 | `flate2` + `tar` (default features off) in `macrunnerbar-macos` to extract the runner `.tar.gz`; entries limited to files, directories and in-tree relative symlinks | no `tar` subprocess whose path handling we cannot test; `unpack_in` refuses `..` and write-through-symlink | shelling out to `/usr/bin/tar` |
| D18 | 2026-11-09 | `libc` in `macrunnerbar-macos` for `killpg`, `waitid(WNOWAIT)` and `kill(pid, 0)`; all `unsafe` lives in `src/sys.rs`, each block with `// SAFETY:` and `clippy::undocumented_unsafe_blocks = deny` | stopping a runner must hit its whole process group; `waitid` peeks at the leader without reaping so the pid stays reserved until the group is signalled | `/bin/kill` subprocess (pid-reuse race, no exit peek) |
| D19 | 2026-11-09 | `tracing-appender` (daily rotation, 14 files) + `tracing-subscriber` (`fmt`, `std` only) in `macrunnerbar-macos`; every event passes `logging::redact` (GitHub token shapes, `Bearer`, registered secrets) before the file | rotating file log under `~/Library/Logs/MacRunnerbar/` with no secrets (hard rule 7) | hand-written rotation, no redaction layer |
| D20 | 2026-11-09 | Start at login writes or removes `~/Library/LaunchAgents/my.ijat.macrunnerbar.plist` only; no `launchctl bootstrap`/`bootout` (refines D4) | launchd loads the directory at the next login; `bootstrap` with `RunAtLoad` would start a second copy now, `bootout` would kill the running app when launchd started it | `launchctl bootstrap/bootout` on every toggle |
| D21 | 2026-11-09 | Runner processes get a cleared environment plus an allow-list (`HOME USER LOGNAME SHELL TMPDIR LANG LC_ALL LC_CTYPE`, `PATH` extended with Homebrew dirs), own process group, stdio to `/dev/null`; pid + start time recorded in `run/<name>.pid` and a recorded pid is signalled only if its start time still matches | the app's environment may hold tokens (`GITHUB_MASTER_CLASSIC_PAT` in a shell-launched app); orphans are found after a crash without ever signalling a recycled pid | inheriting the environment, pid-only records |
| D22 | 2026-11-09 | Token to the Keychain through `security -i` (command on stdin, password as `-X <hex>`), read back to confirm; read with `find-generic-password -w` | the token never appears in an argument list; `-i` may report a failed command in text only, so the read-back decides | `add-generic-password -w <token>` (visible in `ps`) |
| D23 | 2026-11-09 | `JsonSettingsStore` and `SystemClock` live in `macrunnerbar-macos` (not named in the plan's step 3) | the composition root needs real `SettingsStore` and `Clock`; the OS adapter crate is their home; both pass the testkit contracts | implementing them in the app crate |
